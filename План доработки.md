# План доработки PasswordCheckBot: 5 задач



## Задача 1. Генератор паролей

**Что делаем.** Реализуем первую функцию: пользователь просит пароль — бот генерирует.

- Отдельный компонент генерации с параметрами: длина, наборы символов (буквы, цифры, спецсимволы).
- Бот выступает только оболочкой: принимает команду, вызывает компонент, отдаёт результат.
- Гарантируем криптографически стойкую случайность источника.

**Результат этапа:** бот умеет генерировать пароли.


## Задача 2. Оценка стойкости пароля

**Что делаем.** Реализуем вторую функцию: пользователь присылает пароль — бот оценивает его стойкость.

- Отдельный компонент оценки, независимый от генератора.
- Критерии оценки: длина, разнообразие символов, словарные слова и типовые подстановки.
- Ответ пользователю объясняет, что именно слабо, а не только вердикт «слабый/сильный».

**Результат этапа:** бот умеет и генерировать, и оценивать пароли.


## Задача 3. Подключение базы данных с шифрованием

**Что делаем.** Появляется хранилище — и не «просто так», а под потребность задачи 5: помнить пользователя и его отслеживаемые сервисы между запусками.

- Проектируем данные: пользователь (идентификатор, признак включённых уведомлений, дата регистрации) и отслеживаемый сервис (владелец, название сервиса, дата добавления).
- Реализуем слой доступа к данным как отдельный компонент: сохранение, чтение, добавление, удаление записей.
- Автоматическое создание структуры хранилища при первом запуске.
- Сразу закладываем шифрование конфиденциальных полей (прежде всего списка сервисов — он раскрывает цифровое присутствие пользователя): компонент шифрования с операциями «зашифровать/расшифровать», управление ключом (генерация при первом запуске, загрузка из защищённого источника, ключ не хранится вместе с данными и не попадает в репозиторий). Шифрование встроено в слой доступа — остальной код о нём не знает.
- Заменяем все обращения к памяти на обращения к базе.

**Результат этапа:** бот помнит пользователей и их списки сервисов; хранимые данные защищены.


## Задача 4. Проверка пароля по базам утечек (разовая, по запросу)

**Что делаем.** Третья функция: бот отвечает на вопрос «в порядке ли мой пароль прямо сейчас».

- Пользователь присылает пароль; полный пароль внешнему сервису не передаётся — уходит только короткий отпечаток, сравнение идёт по его фрагменту.
- Реализуем компонент обращения к внешней базе утечек: запрос, обработка ответа, обработка отказа сервиса (понятный ответ пользователю вместо необработанной ошибки).
- Пароль существует только в памяти на время обработки и уничтожается после ответа: не логируется, не записывается, не хранится.
- Здесь ничего не накапливается — это разовая проверка, а не слежение.

**Результат этапа:** бот сообщает, засветился ли проверенный пароль в утечках.


## Задача 5. Мониторинг сервисов и уведомления (постоянный, автоматический)

**Что делаем.** Финальная функция, связывающая всё: бот отвечает на вопрос «не случилось ли чего с сервисами, которыми я пользуюсь, пока я не смотрел».

- Пользователь добавляет **названия сервисов**, которыми пользуется (не пароли) — список сохраняется в базе в зашифрованном виде.
- Фоновая задача по расписанию: обходит всех подписанных пользователей, по каждому сервису запрашивает внешнюю базу утечек; соблюдает ограничения на частоту запросов (паузы, кеширование на уровне сервиса).
- Обнаружение новых утечек: сравнение ответа с уже известным; при новой утечке — фиксация факта и постановка уведомления в очередь.
- Отправитель уведомлений: разбирает очередь и сам пишет пользователю — какой сервис, какая утечка, когда, что делать (сменить пароль).
- Управление подпиской: включение и отключение слежения; если пользователь недоступен для бота — подписка гасится, чтобы очередь не копила мёртвые записи.

**Результат этапа:** законченный сервис — настроил один раз, дальше бот работает сам.
